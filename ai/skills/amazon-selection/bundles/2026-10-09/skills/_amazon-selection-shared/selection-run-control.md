# 选品持续执行与恢复合同

运行合同版本：`selection-run-control-v1.1.0`；更新：2026-10-08。

本模块只控制已授权任务的继续、完成和恢复，不创建第二套选品阈值，不自动启动历史任务，不向其他对话发消息。业务门槛仍来自六个Skill及共享模块。

## 1. 任务与运行能力分开

- 用户要求完成数量型任务且授权持续运行时，在当前对话用宿主提供的持久目标机制启用持续Goal；Goal创建只能依据用户明确授权，不能仅因读到本文件自动创建。无授权时给出运行未启用状态，不假称后台工作中。
- 普通Skill文本和检查点不具备唤醒空闲模型的能力。Codex需实际启用Goal；DeepSeek/API宿主需实现读取检查点→调用模型及工具→保存结果→审计→再次调用的循环。不能用“我会继续”替代实际调度，不启动隐藏无限循环、绕过费用预算或私建定时任务。
- 只改规则、打包、初始化、诊断、设置运行层时，不恢复选品。本次2026-10-08用户明确要求先完成升级、不恢复选品；运行器状态为configured_not_started。后续启动需用户下达运行指令，不能从旧消息推定撤销此选择。
- Goal属于当前对话，不自动覆盖另外五个对话。跨对话通知、启动和新子任务仍遵守授权；不得声称修改共享文件已自动唤醒所有任务。

## 2. 两层状态与完成审计

业务状态独立为未完成/已完成；运行状态分别记录configured_not_started、running、user_stopped、blocked、budget_limited、interrupted。运行停止不等于业务完成。

每个任务保存task_id、站点、逐方向目标数、用户授权范围、当前规则/费用版本、原始证据索引、候选ID/语义机会键、每方向漏斗与缺口、动作队列、外部阻塞/恢复条件、交付文件及校验回执、当前所有者和更新时间。状态文件中不得保存密钥。

- 可询价数从仍有效且有询价门槛审计回执的独立机会重算；不沿用旧检查点的宣称总数。分别重算严格询价、受控试询和观察池；受控试询/C档并集超过20%的超额行不计当前交付完成数。回执需指向原始证据，按当前正式规则重判，不能由计数器替代商业审查。
- 同一机会跨方向只计一次，保留最初ID与转路记录；同父体同方案轻微变体不能生成新机会键。真正独立场景按规则给证据说明后才拆分。
- 每方向达请求数且对应当前权威表已通过统一交付检查、可追踪到计数行时，才算该方向完成；阶段表、待补记录和“完成一轮”不等于任务完成。全部请求方向都完成后才允许整个Goal完成。
- 已验证扩展依用户请求和单主题2–3个边界设目标，不默认给50。标签复核按用户提供数量，不偷偷转成新产品发现。
- 实际采购价未知不阻止已合格的询价任务完成；quote_ready任务不等待采购回填才能完成，但不得声称实际利润或开发通过。实际报价撤回产品时按新批次/未完成剩余任务规则明确补替，不静默复写已交版本。

## 3. 继续执行与任务队列

每轮约10个研究目标，或每累计10款可询价保存检查点；有意义的证据增量即时保存。然后审计并领取一个尚未完成、未被其他执行者占用、且依赖已具备的动作。

优先补能决定放行/淘汰的最小证据缺口，其次完成既有市场的分页/父体/经营主体归并、T预注册与窗口、目标配置和包装成本，再从有依据的相邻问题定向扩池。阶段交付可与余下研究交替进行，不要求每次都重生成Excel。

已有有效证据按站点、市场、配置、周期与时效复用。只更新规则时重新判定，不重新抓完整数据；引用的旧通过结论不能覆盖新规则。并行分工用唯一任务/动作所有者，不允许多个模型做同一完整研究。包/规格改变时重核受到影响的需求和费用，不把旧市场总销量套到新方案。

有安全可行研究动作且执行已授权时必须继续，不让用户反复说继续。只在下一轮真正需要新选择、外部授权或新证据时请求必要输入；无需采购、供应商联系或降低规则作为继续条件。

## 4. 停止依据

- 用户叫停：保存检查点并停止；恢复必须按用户新指令。不要把未启动配置标成用户暂停的Goal。
- 系统预算、限额、权限或中断：保存数量、缺口、未执行动作与恢复条件，报告真实原因。不能标为完成，也不能自行提高预算或改变账户设置。
- 单项缺证/时机不成立：该动作或方向待补/观察，其他安全可行方向继续。无日周数据不得每轮重复抓同样月表，恢复条件是取得所需粒度，而不是过几分钟。
- 所有未完成方向没有安全有价值的下一步：先审计分页覆盖、未研究和真缺失、可行替代入口、类型/时间与经济性去向。报告每方向覆盖和缺口；不能仅凭一轮0款、查了很多词或输出了阶段表宣称市场耗尽。
- 若使用Codex Goal的blocked状态，须同一真实阻塞在至少三个连续Goal轮次出现且没有有意义进展，严格按宿主工具合同处理；连续三次函数调用不算三轮。恢复后重新审计，不因历史计数立刻阻塞。无意义工具调用不能伪装进展。
- 临时接口错误先校对参数，再做有限有效重试/可行替代入口并转可执行独立动作；禁止无限重试。两个连续研究轮次没有证据增量时审查策略、覆盖和任务队列，不自动宣称耗尽或降低阈值。

## 5. 可执行审计器

脚本：`scripts/selection-runtime.mjs`（相对于本共享目录）。使用Node运行：

```text
node scripts/selection-runtime.mjs audit /绝对路径/task-state.json
```

返回结构化决策：activation_required、continue、repair_queue、repair_delivery、wait_owned_work、stop_user、stop_budget、audit_blocker或report_blocked；业务completed只在数量与交付回执均齐全时返回。脚本默认只读，不调用模型/MCP、不采购、不配置调度，也不改写业务事实。宿主执行动作后须真实保存证据与状态，再调用审计器；CLI打印continue不表示已调度下一轮。

state.schema.json定义结构与所需字段。状态中的审计回执是研究者对正式规则的核验记录，不是本脚本对销量/趋势/IP真实性的证明；不能手填pass来凑数。CLI核对证据文件和交付文件哈希；内容正确性及工作簿公式/渲染仍按原规则检查。

## 6. 启动与续跑时的宿主适配

Codex收到用户明确的持续执行指令后：get_goal确认当前目标；没有Goal则create_goal，已有相关Goal不重复创建，已有其他目标先报告冲突。未请求token预算时不自行设置预算。后续轮次读任务状态、正式版本和真实Goal状态，执行审计器给出的安全动作并保存证据。只有完成审计通过才update_goal complete。暂停、恢复、预算和blocked遵守运行工具权限，不用本文件覆盖工具合同。

其他宿主：实现同等循环、检查点、任务唯一所有者和用户停止/预算控制；没有这一能力就明确“仅单轮执行，需要宿主续调”，不能把修改提示词说成已启用持续运行。不含API调用代码、账户配置或密钥注入。

官方机制参考：https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex （2026-10-08查阅）。只作运行能力说明，不是选品规则来源。
