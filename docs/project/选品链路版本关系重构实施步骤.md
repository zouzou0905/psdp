# 选品链路版本关系重构实施步骤

> 确认日期：2026-10-09  
> 当前状态：待开始  
> 当前里程碑：先解决选品链路的权限、事务、版本关系、草稿提交、历史保护和查询性能问题；暂不建设六步 AI 闭环。

## 1. 目标与执行方式

本轮重构将现有选品、询价、利润复核、最终选择、竞品和 Listing 历史调整为可由 PostgreSQL 约束、可追溯、可恢复的版本链。

统一原则：

> UUID 主键负责数据库关系；递增版本号只负责展示；Head 指针负责当前状态；版本表负责历史事实；事件表负责解释变化；快照负责还原当时看到的表格。

按本文顺序逐步实施。每一步完成后必须提交修改文件、迁移、测试、数据检查及遗留项报告；只有当前步骤通过验收，才进入下一步。禁止为了赶进度把多个未验证步骤一次性切换。

## 2. 本轮范围

本轮处理：

- 管理员只读权限被用于业务写入的问题；
- 业务版本、审计、幂等和 Outbox 的事务一致性；
- 下游版本对上游版本的 UUID 外键关系；
- `selection_stage_heads` 当前版本指针；
- 草稿、提交和成果有效性拆分；
- 竞品集合独立版本；
- 历史记录软归档及 `ON DELETE RESTRICT`；
- 金额和状态的应用层、数据库层交叉约束；
- 工作台服务端分页、筛选和复合索引；
- 既有 AI 选品表导出功能的兼容性回归。

本轮暂停：

- DeepSeek 选品、利润复核和 Listing 的正式业务编排；
- Sorftime MCP 和用户 Skill 的正式执行链；
- 新增利润复核或 Listing 生成接口；
- 采购询价表、利润表、最终选品表等后续导出功能；
- 未经确认的询价轮次、多供应商等新增业务能力；
- 无关前端改版和其他长期模块扩建。

## 3. 全程不可突破的规则

1. 先备份和检查真实 PostgreSQL 数据，再执行迁移。
2. 第一阶段迁移只加表、加列、加索引，不删除旧字段。
3. 找不到或无法唯一匹配的历史关系进入迁移异常记录，不允许猜测。
4. 正式历史业务内容不可原地改写；生命周期状态变化必须记录流转事件。
5. 根记录不提供物理删除业务接口，只允许带操作者和原因的软归档。
6. 外部网络调用不得放入持有数据库行锁的事务。
7. 所有引用端外键建立与实际查询匹配的索引。
8. 数据库约束、Pydantic 契约、OpenAPI、共享契约和测试必须同步。
9. 每一步都在真实 PostgreSQL 上运行迁移和集成测试，不能只以 SQLite 测试作为验收。
10. 任一步骤失败时停在兼容状态，不能继续删除旧关系或切换全部读取。

## 4. 分步实施计划

### 步骤 0：冻结基线并建立回退点

状态：未开始

工作内容：

- 记录当前 Alembic head、数据库表结构、约束、索引和数据量；
- 备份真实 PostgreSQL 数据库，并验证备份可读取；
- 运行当前 pytest、Ruff、mypy、Alembic check 和关键接口测试；
- 统计每个候选的询价、利润、最终选择、竞品、Listing 版本数量；
- 检查重复版本号、孤儿记录、跨候选疑似错链和空关键字段；
- 固化一组迁移前业务结果及既有导出文件，作为迁移后对照样本。

验收条件：

- 有明确的基线报告、备份位置、当前迁移版本和测试结果；
- 已知异常被列出并分级；
- 能够证明回退时使用哪份备份和哪个代码版本。

停止点：发现无法解释的数据异常或备份不可验证时，不进入步骤 1。

### 步骤 1：修复只读管理员越权写入

状态：未开始

工作内容：

- 管理员默认权限从“全量权限减排除项”改为明确白名单；
- `all_business.read` 只能读取，不能用于询价、最终选择、竞品等写接口；
- 读取范围检查与写入范围检查分离；
- 管理员执行具体业务写入时必须获得明确动作权限及数据范围；
- 为旧会话失效和授权修订增加回归验证。

验收条件：

- 只有 `all_business.read` 的管理员访问所有业务写接口均返回 403；
- 获得专用写权限但不在数据范围内的账号仍不能写入；
- 普通采购、运营现有合法操作不受破坏；
- 权限测试覆盖列表、详情、写入、导出及对象 ID 越权。

停止点：任何只读权限仍能触发数据变化时，不进入步骤 2。

### 步骤 2：增加新版关系结构但不切换业务

状态：未开始

工作内容：

- 为利润复核增加明确的报价 UUID 引用；
- 为最终选择增加明确的利润复核 UUID 引用；
- 建立 `competitor_set_versions` 及竞品条目、要点子表；
- 为 Listing 增加最终选择和竞品集合 UUID 引用边界；
- 建立 `selection_stage_heads`；
- 建立 `selection_flow_events`；
- 增加交接状态、有效性状态、提交人、提交时间及软归档字段；
- 增加必要组合唯一约束和引用端索引；
- 暂时保留旧数字版本字段和旧读取逻辑。

组合关系至少保证：

```text
(selection_id, quotation_id)
(selection_id, profit_review_id)
(selection_id, final_selection_id)
(selection_id, competitor_set_id)
```

验收条件：

- 迁移可在真实 PostgreSQL 成功升级和降级；
- 新增结构不改变现有接口行为；
- A 候选不能通过组合外键引用 B 候选的数据；
- 所有新增外键引用端均有索引；
- 既有导出功能继续通过。

停止点：迁移破坏现有接口、导出或数据时，不进入步骤 3。

### 步骤 3：回填历史 UUID 关系和 Head

状态：未开始

工作内容：

- 按现有 `(selection_id, version)` 将旧数字关系映射为 UUID；
- 为当前可判定结果建立 Head 指针；
- 将旧竞品数据转换为独立竞品集合版本，保留原录入人和时间；
- 建立持久化迁移异常记录或等价的受控异常报告；
- 对无法匹配、重复匹配或来源不明的数据停止自动处理；
- 生成回填前后数量、关系和校验和对账报告。

验收条件：

- 所有可自动迁移数据均能沿 UUID 关系追溯完整上游；
- 旧数字关系和新 UUID 关系查询结果一致；
- 异常数据没有被猜测、覆盖或删除；
- Head 只指向同一候选的有效版本。

停止点：存在未解释的不一致时，不切换新写入。

### 步骤 4：建立原子业务事务

状态：未开始

工作内容：

- 建立共享 SQLAlchemy Session 的工作单元；
- 统一锁定顺序：先候选根记录，再 Head，必要时再锁相关版本；
- 在同一事务中处理业务版本、Head、失效传播、流转事件、审计、幂等记录和 Outbox；
- 正式命令要求 `expected_revision` 和幂等键；
- 相同幂等键重复请求返回同一业务结果，不产生新版本；
- 外部调用和文件生成不进入数据库事务；
- 失败注入验证任一写入失败时整笔事务回滚。

验收条件：

- 审计失败不会留下已提交业务版本；
- Outbox 或 Head 更新失败不会留下半完成状态；
- 并发旧 revision 返回 409；
- 重复幂等请求只产生一个正式版本；
- 事务持锁时间可控，代码中不存在事务内 DeepSeek/MCP/HTTP 调用。

停止点：仍存在业务成功但审计、事件或Head缺失的路径时，不进入步骤 5。

### 步骤 5：实现草稿、提交和有效性语义

状态：未开始

工作内容：

- 先以采购询价作为第一条完整实现；
- 保存草稿与正式提交使用不同命令语义；
- 第一版每条候选、每个阶段只允许一个共享活动草稿；
- 草稿可修改并使用 `draft_revision`；
- 提交时复制草稿内容，生成新的不可变正式版本；
- Head 分别指向当前草稿、当前已提交和当前有效版本；
- 新报价提交后将依赖的利润、最终选择和 Listing 标记为待复核或被取代；
- 退回、重新提交和过期均记录流转事件。

验收条件：

- 保存询价草稿不会改变当前正式业务阶段和下游有效性；
- 提交才创建正式版本和下游影响；
- 修改草稿不改写旧提交版本；
- 新报价提交后旧下游结果仍可查，但不能作为新的当前输入；
- 缺失、零、估算、失败、不可用和已确认语义可被准确保存。

停止点：草稿仍可能静默覆盖正式版本时，不进入步骤 6。

### 步骤 6：切换下游 UUID 关系并分离竞品版本

状态：未开始

工作内容：

- 利润复核正式引用报价 UUID；
- 最终选择正式引用利润复核 UUID；
- 竞品集合引用最终选择 UUID；
- Listing 边界引用最终选择及竞品集合 UUID；
- 保存竞品时只创建新的竞品集合版本，不创建最终选择版本；
- 草稿竞品允许不完整，提交时校验 3 条竞品且每条 5 个非空要点；
- 新竞品集合提交只影响依赖的 Listing，不影响报价、利润和最终选择事实。

验收条件：

- 更新竞品不会增加最终选择版本，也不会替换原决策人；
- 任一下游结果可通过 UUID 外键追溯完整输入链；
- 错误跨候选引用被 PostgreSQL 拒绝；
- 竞品位置和要点位置唯一，正式提交满足 3×5。

停止点：新旧引用结果不一致或决策历史发生变化时，不进入步骤 7。

### 步骤 7：双读校验并切换 Head 查询

状态：未开始

工作内容：

- 在限定期间同时按旧数字关系和新 UUID 关系读取；
- 记录并监控两种读取结果的不一致；
- 工作台当前结果改为读取 Head，不再依靠版本倒序取第一条；
- 根记录 `stage` 仅作为查询投影，在同一事务中与 Head 保持一致；
- 历史页面继续读取明确版本，不通过 Head 冒充历史。

验收条件：

- 双读对账无未解释差异；
- 当前结果查询稳定指向 Head；
- 旧版本晚到、旧请求重试不能覆盖新 Head；
- 迁移前后的历史业务结果一致。

停止点：Head 与版本链不一致时，不收紧旧字段约束。

### 步骤 8：收紧约束和历史保护

状态：未开始

工作内容：

- 将已完成回填的 UUID 引用改为非空；
- 验证组合外键和 CHECK 约束；
- 正式历史外键切换为 `ON DELETE RESTRICT`；
- 根记录只允许软归档，保存 `archived_at`、`archived_by`、`archive_reason`；
- 增加金额、状态、提交人、提交时间和淘汰理由的交叉约束；
- 旧数字字段停止承担关系定位，仅临时保留兼容或展示作用；
- 在线迁移优先使用 `NOT VALID`、回填和 `VALIDATE CONSTRAINT`，避免一次长时间锁表。

验收条件：

- 删除根记录不能级联删除正式历史；
- 归档后历史仍可按权限查询；
- 绕过 API 的错误关系和错误金额状态会被 PostgreSQL 拒绝；
- 所有新约束在真实数据上完成验证。

停止点：存在无法验证的约束或不可解释的脏数据时，不删除任何旧字段。

### 步骤 9：服务端分页和索引优化

状态：未开始

工作内容：

- 选品列表增加店铺、阶段、关键字、limit 和游标参数；
- 使用 `(updated_at, selection_id)` 组成稳定游标；
- 建立匹配查询路径的复合索引；
- 正常列表默认过滤已归档记录，并建立相应部分索引；
- 前端改为使用后端分页及筛选，不再一次加载全部记录；
- 使用 `EXPLAIN (ANALYZE, BUFFERS)` 验证真实 PostgreSQL 查询计划。

建议索引基线：

```text
(store_id, stage, updated_at DESC, selection_id DESC)
WHERE archived_at IS NULL
```

验收条件：

- 深页查询不使用 OFFSET；
- 翻页过程中顺序稳定，不重复或遗漏记录；
- 查询命中预期复合或部分索引；
- 前端不再持有全部候选后自行过滤；
- 权限和店铺范围在分页查询中保持有效。

### 步骤 10：清理旧关系并完成重构验收

状态：未开始

工作内容：

- 停止旧数字字段的双写和旧读取路径；
- 根据兼容需要决定旧版本号字段仅保留展示还是后续删除；
- 清理不再使用的仓储查询和临时迁移代码；
- 更新数据模型、流转规则、OpenAPI、共享契约和运维说明；
- 完成全量回归、恢复演练及迁移前后结果对账；
- 明确后续是否恢复询价导出和六步 AI 闭环建设。

最终验收条件：

1. 任一当前结果都能沿 UUID 外键追溯完整输入链；
2. A 候选不能引用 B 候选的阶段版本；
3. 正式历史不会被根记录删除而级联消失；
4. 草稿修改不影响当前正式结果；
5. 竞品更新不产生新的最终选择版本；
6. 业务、Head、事件、审计、幂等和 Outbox 原子提交；
7. 迁移异常全部有人工结论，不存在自动猜测关系；
8. 工作台使用服务端游标分页和预期索引；
9. 既有选品表导出、认证、店铺隔离和权限撤销继续通过；
10. 真实 PostgreSQL 升级、回退及恢复演练通过。

## 5. 每一步的统一交付格式

执行人员完成每一步后必须报告：

- 本步骤完成范围及未完成范围；
- 修改文件；
- Alembic 迁移编号和升级/回退结果；
- 数据回填数量、异常数量和处理方式；
- 权限、事务和接口行为变化；
- pytest、Ruff、mypy、Alembic check 结果；
- 真实 PostgreSQL 集成测试结果；
- 对既有导出和前端契约的影响；
- 是否满足进入下一步的全部条件。

报告不能仅写“测试通过”，必须给出测试数量、被跳过项及跳过原因。当前步骤未满足验收条件时，状态保持“进行中”或“阻塞”，不得自行开始下一步骤。

## 6. 决策待确认项

以下内容不阻塞步骤 0 至步骤 4，但在相应步骤实施前必须确认：

- 后续是否允许同一候选存在多个用户个人草稿；第一版暂按单个共享草稿设计；
- 多供应商和询价轮次是否纳入下一轮业务扩展，本轮不主动实现；
- 软归档后的默认保留期限；未确认前永久保留；
- 旧数字版本字段在最终阶段保留为展示冗余，还是在稳定运行后删除；
- 数据迁移异常的最终审核岗位。
