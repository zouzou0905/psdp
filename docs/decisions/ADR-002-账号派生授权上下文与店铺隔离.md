# ADR-002：账号派生授权上下文与店铺隔离

- 状态：已确认
- 日期：2026-10-07

## 决策

客户端不再选择或切换运营、采购、美工、管理员身份。登录后由后端根据账号配置返回角色、可见板块、有效动作权限、数据范围、默认落点和授权修订号。

角色提供默认权限集合；管理员可为账号配置角色、额外动作权限、可见板块和店铺范围。实际请求必须同时通过账号状态、板块、权限和对象范围校验。运营业务数据以店铺为强制隔离维度，并在仓储查询中施加过滤。

授权修改递增 `authorization_revision`，使旧 Token 立即失效。所有授权修改写追加式审计日志。店铺凭证只保存安全存储引用，业务接口不得返回凭证明文。

## 原因

前端角色选择不能构成安全边界，也无法防止修改 URL、对象 ID 或请求参数后的越权。独立的板块分配与动作权限支持多岗位账号，而显式数据范围使同一岗位内的店铺隔离可审计、可测试。

## 后果

- 前端只消费 `/me/access-context`，不自行推导或扩大权限。
- 权限或范围变更会中断目标账号的旧会话，客户端需重新登录。
- 管理员的全局读取能力不绕过高风险审批。
- 未来外部连接器必须接收统一权限和 Task/Run/Action 上下文。
