# 账号、板块权限与店铺范围

## 授权判定

登录请求不接受角色或板块参数。后端从账号配置解析访问上下文：

```text
账号 -> 角色 -> 可见板块 -> 动作权限 -> 组织/团队/店铺范围
```

一次访问必须同时满足账号有效、目标板块已分配、动作权限已授予、目标对象位于数据范围。角色用于汇集默认权限，但授权判定不能只检查角色名称。多板块账号只能使用管理员已分配的板块。

## 运营店铺隔离

- 运营列表在 SQL 查询中增加 `store_id IN (authorized_store_ids)`；范围为空时结果为空。
- 运营详情使用相同条件按 ID 查询，越权对象对调用方表现为不存在。
- 后续创建和修改命令必须在应用服务执行 `store_id` 范围检查，并在写入前再次校验。
- 未指定店铺的运营汇总仅聚合账号已授权店铺。
- `stores.credential_ref` 只能保存 Secret Manager 等安全存储中的不透明引用。API 不接收或返回店铺凭证明文。

采购和美工继续按其业务所需的组织、团队、负责人范围过滤；店铺授权不会自动授予采购报价、供应商或系统日志权限。

## 授权变更和会话失效

每个账号持有单调递增的 `authorization_revision`。Access Token 写入签发时的修订号，但不写入权限列表。每次请求从 IAM 仓储重新解析账号，并比较修订号。管理员修改角色、直接权限、板块或店铺范围后，修订号在同一事务中递增，旧 Token 随即返回 401。

更新请求携带 `expected_authorization_revision` 做乐观并发控制；冲突返回 409。成功变更以追加方式记录审计日志，其中包含脱敏后的变更前后状态、操作者和 trace ID。

## 管理员边界

管理员需要 `admin` 板块以及相应动作权限才能访问账号和店铺管理接口。管理员可查看和配置授权，但 `admin` 身份不构成采购、发布、广告预算或其他高风险动作的审批；这些动作仍须经过独立审批规则。

## 外部系统上下文

未来所有 `CapabilityGateway`、`MCPClientAdapter`、`MarketplaceConnector`、`ERPConnector` 和 `StoreCredentialProvider` 调用必须接收 `ExternalCallContext`，至少携带：

```text
user_id, module_code, store_id, permission_scope, task_id, run_id, action_id
```

适配器不是授权来源。调用前仍由应用服务完成板块、动作、数据范围和审批校验，外部写入继续建立 receipt 与状态回查链路。
