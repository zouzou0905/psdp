# 六步选品流程字段、状态与接口

本文记录 2026-10-08 当前阶段的首版实现边界，依据 ADR-003。四类“表格”是同一
`selection_record` 聚合在不同阶段的数据库视图，不是四套互相复制的数据。

> 本文描述当前基础实现。后续交接、草稿/提交、退回、成果失效和验收要求以 `docs/requirements/选品表格流转规则.md` 为依据；新增规则尚需开发，不应把这里已有的接口视为完整流转能力。

## 数据与版本

- 选品根记录保存店铺、平台、产品名、来源类型/引用/快照/版本、负责人、阶段和乐观锁修订号。
- 采购询价采用追加版本，保存供应商、单价、币种、数值状态、MOQ、交期、单件运费、其他成本、目标售价、备注、登记人和提交状态。现有写接口产生 `submitted` 版本，尚未开放草稿保存。
- 利润复核采用追加版本并引用询价版本，保存金额/利润率、数值状态、建议、解释、缺失项和任务运行引用。公式和门槛尚未确认，不在代码中写死。
- 最终选品采用追加版本并引用利润复核版本，保存运营人工决定、理由和操作人。
- 竞品随最终选品版本保存；仅 `selected` 决定可写入，严格要求三条，每条标题和五条要点。
- Listing 草稿按版本保存并归运营工作台专属；普通采购不可读取。管理员需要明确的 Listing 文案权限。当前未开放生成、编辑或审核操作。

## 状态

业务阶段为：`sourced -> quoted -> profit_reviewed -> final_selected | final_rejected`。
修改询价会回到 `quoted`，旧的利润、最终选择和文案仍作为历史版本保留，但不作为当前成果返回。

AI 任务状态独立为 `planned | queued | running | succeeded | failed | cancelled`。当前只提供查询边界，不调用 DeepSeek、Skill 或 Sorftime MCP，也不创建伪成功结果。

## HTTP 接口

- `GET /api/v1/selection-records`
- `GET /api/v1/selection-records/{selection_id}`
- `GET|PUT /api/v1/selection-records/{selection_id}/quotation`
- `GET /api/v1/selection-records/{selection_id}/profit-review`
- `GET|PUT /api/v1/selection-records/{selection_id}/final-selection`
- `GET|PUT /api/v1/selection-records/{selection_id}/competitors`
- `GET /api/v1/selection-records/{selection_id}/ai-tasks`
- `GET /api/v1/selection-records/{selection_id}/listing-draft`（仅运营或被显式授权的管理员）
- `POST /api/v1/selection-exports`（`stage=quotation` 时需要采购/管理员板块及 `quotation.export`）
- `GET /api/v1/selection-exports/{export_id}`
- `GET /api/v1/selection-exports/{export_id}/download`

列表和详情在 SQL 查询中按授权店铺过滤，写入同时校验板块、动作权限、对象店铺和 `expected_revision`。
